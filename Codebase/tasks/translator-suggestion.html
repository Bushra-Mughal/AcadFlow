Urdu-English Translator for AcadFlow

Integration proposal, architecture, and step-by-step implementation using the Google Text Translation capability.

1. Why Add Urdu-English Translation?

AcadFlow supports students worldwide. Many Pakistani and Indian students are more comfortable reading Urdu for instructions but submit work in English. Adding an in-app translator lets students:

  • Translate assignment titles and descriptions between Urdu and English.
  • Convert AI chat messages from English to Urdu for easier comprehension.
  • Translate pasted notes from Urdu into English for academic submission.
  • Toggle the entire app UI or selected content to their preferred language on demand.
Language codes: ur for Urdu, en for English. The Google Cloud Translation API supports both directions with automatic source detection.

2. Integration Architecture

Follow the existing AcadFlow pattern: route translation through a Supabase Edge Function so the platform API key is never exposed to the browser.

Frontend

  • New "Translate" button in AI Assistant, AI Analyzer, and Assignment/Project forms.
  • Language selector: en â†’ ur, ur â†’ en, or auto â†’ ur.
  • Supabase client calls supabase.functions.invoke('urdu-english-translator', { body }).

Backend

  • New Edge Function urdu-english-translator in supabase/functions/.
  • Reads INTEGRATIONS_API_KEY from environment.
  • Calls Google Text Translation gateway with q, target, and optional source.
  • Returns JSON with translatedText and detectedSourceLanguage.

3. Proposed Edge Function

Create supabase/functions/urdu-english-translator/index.ts:

import { corsHeaders } from '../_shared/cors.ts';

const TRANSLATE_URL = 'https://app-biof3pfof94x-api-GaDwZ8DX7jPY.gateway.appmedo.com/language/translate/v2';

Deno.serve(async (req) => {
  if (req.method === 'OPTIONS') {
    return new Response(null, { headers: corsHeaders });
  }

  try {
    const { q, target, source, format = 'text' } = await req.json();

    if (!q || !target) {
      return new Response(
        JSON.stringify({ error: 'q and target are required' }),
        { status: 400, headers: { ...corsHeaders, 'Content-Type': 'application/json' } }
      );
    }

    const apiKey = Deno.env.get('INTEGRATIONS_API_KEY');
    if (!apiKey) {
      return new Response(
        JSON.stringify({ error: 'API key not configured' }),
        { status: 500, headers: { ...corsHeaders, 'Content-Type': 'application/json' } }
      );
    }

    const body: Record<string, string> = { q, target, format };
    if (source) body.source = source;

    const upstream = await fetch(TRANSLATE_URL, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'X-Gateway-Authorization': `Bearer ${apiKey}`,
      },
      body: JSON.stringify(body),
    });

    if (upstream.status === 429 || upstream.status === 402) {
      return new Response(await upstream.text(), {
        status: upstream.status,
        headers: { ...corsHeaders, 'Content-Type': 'application/json' },
      });
    }

    if (!upstream.ok) {
      return new Response(
        JSON.stringify({ error: `Upstream error: ${upstream.status}` }),
        { status: 502, headers: { ...corsHeaders, 'Content-Type': 'application/json' } }
      );
    }

    const data = await upstream.json();
    return new Response(JSON.stringify(data), {
      headers: { ...corsHeaders, 'Content-Type': 'application/json' },
    });
  } catch (error) {
    console.error('[urdu-english-translator] error:', error);
    return new Response(
      JSON.stringify({ error: error.message || 'Internal server error' }),
      { status: 500, headers: { ...corsHeaders, 'Content-Type': 'application/json' } }
    );
  }
});

SecurityINTEGRATIONS_API_KEY is never sent to the client. CORS headers are shared with the other Edge Functions.

4. Frontend Translation Hook

Create a reusable hook in src/hooks/use-translation.ts:

import { useState, useCallback } from 'react';
import { supabase } from '@/db/supabase';

interface TranslationResult {
  translatedText: string;
  detectedSourceLanguage?: string;
}

export function useTranslation() {
  const [translating, setTranslating] = useState(false);
  const [error, setError] = useState(null);

  const translate = useCallback(async (
    text: string,
    target: 'ur' | 'en',
    source?: 'ur' | 'en'
  ): Promise<TranslationResult | null> => {
    if (!text.trim()) return null;
    setTranslating(true);
    setError(null);
    try {
      const { data, error } = await supabase.functions.invoke('urdu-english-translator', {
        body: { q: text.trim(), target, source },
      });
      if (error) throw error;
      return data.data.translations[0] as TranslationResult;
    } catch (err) {
      const msg = err instanceof Error ? err.message : 'Translation failed';
      setError(msg);
      return null;
    } finally {
      setTranslating(false);
    }
  }, []);

  return { translate, translating, error };
}

7. Database Changes (Optional)

Store translation preferences per user:

-- Add to existing profiles table
ALTER TABLE profiles ADD COLUMN IF NOT EXISTS preferred_language text DEFAULT 'en';

-- Track translation history (optional)
CREATE TABLE IF NOT EXISTS translations (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  source_text text NOT NULL,
  translated_text text NOT NULL,
  source_language text,
  target_language text NOT NULL,
  created_at timestamptz DEFAULT now()
);

ALTER TABLE translations ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can view their own translations"
  ON translations FOR SELECT TO authenticated USING (user_id = auth.uid());
CREATE POLICY "Users can create their own translations"
  ON translations FOR INSERT TO authenticated WITH CHECK (user_id = auth.uid());

With RLS in place, users can only see their own translation history. This is useful for re-translating prior notes without calling the API again.

  9. Optionally create the translations table and history UI.
  10. Run lint and tests, then deploy.

9. Engineering Considerations

  • Cost: Translation is billed per API call. Debounce inputs and avoid auto-translating every keystroke.
  • Privacy: Never send sensitive content to the API. Add a tooltip warning when translating confidential research.
  • Formatting: Use format: 'html' when translating rich content from the AI analyzer; use format: 'text' for plain text.
  • Fallback: If the API fails, show the original text and a toast error so the user is never blocked.
  • Right-to-left: Urdu is RTL. Add dir="rtl" to Urdu text containers and use a Urdu-compatible font (e.g., Jameel Noori Nastaleeq or system Arabic fonts).
  • Transliteration: Some users type Urdu in Roman script (e.g., "Assalam-o-Alaikum"). The API may detect this as English. Provide a manual source selector.

10. Summary

The Urdu-English translator integrates cleanly with AcadFlow's existing Supabase Edge Function and shadcn/ui architecture. The implementation reuses the established patterns (shared CORS, supabase.functions.invoke, hooks, and reusable buttons) and adds a practical accessibility feature for students who work across both languages.

Recommended first step: Deploy the Edge Function and add a TranslateButton to the AI Assistant assistant messages. This gives immediate value with minimal UI changes.
