9. User Data Path Summary

  1. Registration: User chooses username â†’ is_username_available RPC â†’ Supabase Auth creates username@miaoda.com â†’ trigger creates profiles row â†’ username/Gmail stored.
  2. Login: User enters credentials â†’ signInWithPassword â†’ JWT stored in Supabase client â†’ profiles loaded â†’ RouteGuard grants access.
  3. Dashboard: Fetches assignments and projects â†’ computes stats â†’ renders RankBar, progress bars, upcoming deadlines.
  4. Creating Assignment: Form data â†’ INSERT assignments â†’ trackActivity('created') â†’ activities row.
  5. Completing Assignment: Status update â†’ trackActivity('status_changed') â†’ award_points RPC â†’ user_stats updated â†’ check_and_award_badges â†’ UI toasts.
  6. Creating Project: INSERT projects with creator_id â†’ invite members via find_user_by_email RPC â†’ INSERT project_members.
  7. Uploading File: File â†’ Supabase Storage bucket â†’ public/signed URL â†’ INSERT files with metadata â†’ award_points('file_uploaded').
  8. AI Chat: Message + context â†’ ai-assistant Edge Function â†’ Gemini stream â†’ INSERT chat_messages â†’ award_points('ai_session').
  9. AI Analysis: Content â†’ ai-analyzer Edge Function â†’ Gemini JSON â†’ INSERT analysis_history â†’ UI renders score breakdown.
  10. Theme Switch: Theme selection â†’ CSS variables injected â†’ localStorage persisted â†’ CinematicBackground canvas rendered if active.
  11. Activity Log: Reads activities table filtered by user â†’ normalizes @miaoda.com emails to @acadflow.
  12. Achievements: Loads badges + user_badges + user_stats â†’ computes progress and locked/unlocked state.
  13. Logout: signOut() â†’ session cleared â†’ RouteGuard redirects to login.

11. RLS & Security Flows

flowchart LR A[Frontend Request] --> B[Supabase API] B --> C{RLS Policy} C -->|Allowed| D[PostgreSQL Row] C -->|Denied| E[Permission Error] D --> F[Triggers / RPCs] F --> G[user_stats, activities, badges]
  • assignments: user_id = auth.uid() for all operations.
  • projects: Creator or member can read/update; only creator can delete.
  • project_members: Creator can add/remove; members can view.
  • files: Owner can CRUD; project members can view project files.
  • profiles: Own profile access; admins full access via has_role.
  • Username availability: Anonymous RPC is_username_available uses SECURITY DEFINER to bypass RLS.
  • Points: award_points RPC uses SECURITY DEFINER so users cannot manually update stats.
